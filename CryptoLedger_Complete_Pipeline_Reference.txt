                    PART A — PLATFORM OVERVIEW & DIRECTORY TOPOLOGY

################################################################################
################################################################################

The CryptoLedger platform is a unified forensic evidence custody system that
integrates three independent, purpose-built subsystems into a seamless
pipeline:

  1. Entry Station   — FIDO2 credential enrollment
  2. CyberChain      — Blockchain-anchored session management
  3. PeakLedger      — Cryptographic video forensic engine

The platform solves two fundamental problems in digital forensics:

  Problem 1: Who touched the evidence?
    Solved by CyberChain's FIDO2 biometric authentication and Ethereum smart
    contract session anchoring. Every examiner session is immutably recorded
    on-chain with entry time, exit time, examiner identity, and a SHA-256 hash
    of all modifications.

  Problem 2: Has the video evidence been tampered with?
    Solved by PeakLedger's Two-Layer Decoupled Forensic Architecture. Layer 1
    hashes every compressed packet into a Merkle Tree for bitwise verification.
    Layer 2 extracts semantic attributes (faces, plates, signals, clothing) for
    deep forensic auditing.

                    PART B — ENTRY STATION (entry/)

################################################################################
################################################################################

The Entry Station is the very first touchpoint in the CryptoLedger pipeline. Its
sole purpose is to pre-enroll forensic examiners and administrators into the
system by capturing their real Name and a genuine FIDO2 biometric passkey from
their smartphone via Bluetooth QR code.

EMBEDDED HTTP SERVER:
  class EnrollmentHttpHandler(http.server.BaseHTTPRequestHandler):

    log_message(): Overridden to suppress console clutter (does nothing).

    send_cors(): Sends Access-Control-Allow-Origin: *, Allow-Methods: GET/POST/
    OPTIONS, Allow-Headers: Content-Type.

    do_OPTIONS(): Returns 200 with CORS headers (preflight support).

    do_GET():
      Parses URL path and query parameters.
      Routes:
        /enroll or / :
          Retrieves session from active_qr_sessions by query param "session".
          Falls back to query param "user" for username.
          Renders full HTML enrollment page via get_enrollment_html().
          Returns 200 with Content-Type: text/html; charset=utf-8.

        /poll :
          Returns JSON of the session object for the given session_id.
          If session not found, returns {"status": "NOT_FOUND"}.
          Content-Type: application/json.

        All other paths: 404.

    do_POST():
      Routes:
        /submit or /api/verify :
          Reads Content-Length header, reads body, parses as JSON.
          Extracts session_id and credential_id from request body.

          VALIDATION (critical security):
            - If session_id is missing, empty, or not in active_qr_sessions: 400
            - If credential_id is missing, empty, or whitespace-only: 400
            This prevents false verification when the user cancels the WebAuthn
            prompt (which sends no credential_id).

          On valid credential:
            Sets active_qr_sessions[session_id]["status"] = "VERIFIED"
            Sets active_qr_sessions[session_id]["credential_id"] = cred_id
            Sets active_qr_sessions[session_id]["client_device"] = client_dev
            Returns 200 with {"success": true, "credential_id": cred_id}

          On exception: 500.
        All other paths: 404.

  start_embedded_qr_server():
    Attempts to bind the server to ports in order: 8089, 8090, 8091, 8888, 0.
    Port 0 lets the OS assign any available port.
    Starts the server in a daemon thread (threading.Thread, daemon=True).
    Updates global qr_server_port with the actual bound port.
    Returns the port number.

PeakLedger is the computational forensic engine. It is written in C++20 with
NVIDIA CUDA for GPU acceleration and Python for the GUI frontend.

CORE ARCHITECTURE: TWO-LAYER DECOUPLED FORENSIC SYSTEM
=======================================================

Layer 1 — Bitstream Merkle Tree Cryptographic Anchor:
  Operates directly on compressed video container packets (NAL units).
  Every packet (I-frame, P-frame, B-frame) is hashed:
    H_leaf = SHA256(CanonicalAnnexB_NAL || PTS || DTS || LeafIndex)
  Leaf hashes are assembled into a balanced binary Merkle Tree.
  The 32-byte Merkle Root seals the entire video.
  Verification: re-hash packets, rebuild tree, compare roots.
  Speed: >5,400,000 packets/second. No GPU decoding needed.
  Guarantees: 100% bitwise cross-GPU/cross-CPU determinism.

Layer 2 — Forensic Intelligence & Attribute Engine:
  Operates on decoded video frames (via NVIDIA NVDEC).
  Extracts semantic attributes per detected entity:
    - ArcFace 512-D facial embeddings (cosine sim >= 0.72)
    - License plate OCR with Levenshtein edit distance (D <= 1)
    - Traffic signal states (RED=0, AMBER=1, GREEN=2, UNKNOWN=255)
    - Countdown timer integers (|Δt| <= 1s)
    - Pedestrian torso/lower-body HSV clothing palettes (10 color bins)
  Stored in SQLite Content-Addressable Storage (CAS).

Two-Tier Verification:
  1. Layer 1 scans ALL packets (zero-decode). If Merkle roots match: AUTHENTIC.
  2. If mismatch detected: isolate divergent interval [PTS_start, PTS_end].
     Selectively decode ONLY those frames via NVDEC.
     Run Layer 2 attribute comparison against baseline.

12-PHASE FORENSIC PIPELINE
===========================

Phase 1: Container Demuxing & Annex B Bitstream Ingestion
  Opens MP4/MKV/AVI via FFmpeg libavformat.
  Extracts raw AVPacket bitstreams WITHOUT decoding.
  Normalizes AVCC length headers to Annex B start codes (0x000001/0x00000001).
  Ingests ALL picture types: I, P, B frames. Zero skipping.

Phase 2: Layer 1 Canonical Leaf Hashing & Merkle Tree
  H_leaf = SHA256(CanonicalNAL || PTS || DTS || LeafIndex)
  Builds balanced binary Merkle Tree.
  Seals with immutable 32-byte Merkle Root.

Phase 3: NVDEC Hardware Video Decoding
  AVCodecContext with AV_HWDEVICE_TYPE_CUDA.
  Decodes into NV12 surfaces in GPU VRAM (d_y_plane, d_uv_plane).
  Extracts AVMotionVector for residual analysis.
  Zero host memory copies.

Phase 4: CUDA Luminance/Chrominance Preprocessing
  Stream A: Spatial macro-grid (32x16 = 512 cells) with warp-level shuffle reductions.
  Stream B: Bilinear resize to 640x640, normalize [0,1], NCHW layout.
  Both run concurrently on separate CUDA streams.

Phase 5: TensorRT YOLO Inference
  Double-buffered execution slots (enqueueV3).
  8,400 anchor candidates across feature pyramid.
  80 COCO categories. Confidence threshold filtering.

Phase 6: Motion Tracking, NMS & Cyclist Pairing
  Class-wise NMS (IoU 0.45).
  Hungarian/greedy centroid association.
  Cyclist pairing: person + bicycle within 160px -> paired, bicycle suppressed.
  Boustrophedon serpentine 1D mapping for spatial locality.

Phase 7: Layer 2 Forensic Attribute Extraction
  ArcFace 512-D facial embeddings (upper 20% cephalic region, L2 normalized).
  License plate OCR (alphanumeric string extraction).
  Traffic signal classification (RED/AMBER/GREEN/UNKNOWN) + countdown timer.
  Pedestrian clothing HSV palettes (torso + lower body, 10 discrete bins).

Phase 8: Track-Aware Reference Crop Lifecycle
  Crop on track birth (confidence >= 0.40).
  Crop on confidence upgrade (+0.15).
  Result: >93.7% storage reduction (29 crops from 459 entity records in 283 frames).

Phase 9: Dual Blockchain + Forensic Metadata Persistence
  vector_frames_blockchain: per-frame macro-grid signatures, SHA-256 block hashes.
  semantic_evidence_blockchain: temporal window entity trajectories.
  forensic_frame_metadata: Layer 2 CAS records.
  All committed to evidence/ledger.db via ACID SQLite.

Phase 10: Layer 1 Zero-Decode Bitstream Verification
  Re-demuxes suspect video.
  Hashes packets, rebuilds candidate Merkle Root.
  Compares against baseline root in SQLite.
  Speed: >5,400,000 packets/sec (>120x real-time).
  10-hour video: verified in <160ms. Zero GPU usage.

Phase 11: Layer 2 Selective NVDEC Deep Audit
  Only triggered on Layer 1 mismatch.
  Isolates [PTS_start, PTS_end] divergence interval.
  Decodes ONLY those frames via NVDEC.
  ArcFace audit: S_cosine < 0.72 -> face swap alert.
  OCR audit: D >= 2 -> fraudulent plate.
  Signal audit: state mismatch or timer skip > 1s.
  Clothing audit: dominant color bin shift.

Phase 12: NIST SP 800-86 HTML Report Generation
  Standalone HTML (evidence/Forensic_Report.html).
  All images/GIFs/CSS embedded as base64 data URIs.
  Cryptographic chain traversal badges.
  NIST SP 800-86 + FRE 902(13)/(14) compliance.


LAPTOP VRAM OPTIMIZATION (RTX 3050 4-6GB):
  VramProfile::LAPTOP mode limits TensorRT workspace to 256MB per context.
  Throttled double-buffered staging: 2 concurrent frame slots.
  Direct NV12 surface ingestion (no RGB conversion = 50% VRAM savings).
  Target footprint: <2.5GB total.

Here is the complete, step-by-step lifecycle of a single forensic session:

PRE-SESSION (Entry Station):
  1. Admin runs entry/entry_station.py --gui (or --cli).
  2. Enters examiner's Name (e.g., "Inspector_Sharma").
  3. Selects Role: "user (Forensic Examiner)" or "admin (Administrator)".
  4. Clicks "Launch Phone Bluetooth Passkey Prompt".
  5. Browser opens with WebAuthn QR code page.
  6. Examiner scans QR with phone camera.
  7. Phone connects via Bluetooth, prompts for fingerprint.
  8. Fingerprint confirmed -> credential_id captured.
  9. Entry Station shows "🟢 PASSKEY CAPTURED VIA PHONE!"
  10. Clicks "Save User & Passkey to Database".
  11. Name + Role + credential_id committed to cyberchain.db.
  12. User is now pre-enrolled and can use CyberChain.

SESSION START (CyberChain app.py):
  13. Examiner runs CyberChain/app.py.
  14. Login card appears: enters Name, clicks "Enter Passkey".
  15. User looked up in cyberchain.db (or created if new).
  16. Auth server starts on port 8088.
  17. Auth session created (uuid4.hex[:12], status=PENDING).
  18. Browser opens: http://localhost:8088/auth?session={id}&user={name}
  19. WebAuthn page displayed with Bluetooth QR + Windows Hello options.
  20. Examiner authenticates via phone fingerprint or Windows Hello.
  21. Credential verified -> session status = VERIFIED.
  22. CyberChain polls at 500ms, detects VERIFIED.
  23. Role retrieved from database.
  24. Session ID generated: sess_{uuid4.hex[:8]}.
  25. Entry time recorded (UTC ISO 8601).
  26. Anvil EVM blockchain node spawned on port 8545 (background, no window).
  27. Wait for JSON-RPC readiness (up to 12 seconds).
  28. Initial session change recorded: "Session initialized by authorized examiner..."
  29. PeakLedger UI launched: pythonw.exe peakledger/ui/main.py (no console, cwd=peakledger/).
  30. CyberChain window hides (self.hide()).
  31. PeakLedger monitor timer starts (1000ms intervals).

FORENSIC ANALYSIS (PeakLedger):
  32. PeakLedger UI opens as the only visible window.
  33. Examiner loads baseline video (sample_pristine.mp4).
  34. C++ backend ingests video through 12-phase pipeline.
  35. Layer 1 Merkle Tree built from all packet hashes.
  36. Layer 2 attributes extracted (faces, plates, signals, clothing).
  37. Dual blockchains + forensic metadata committed to evidence/ledger.db.
  38. Examiner loads suspect video (sample_suspect.mp4).
  39. Layer 1 zero-decode verification at >5.4M packets/sec.
  40. If tampering detected: Layer 2 selective NVDEC deep audit on divergent interval.
  41. tamper_audit_report.json written with verdict, Merkle root, intervals.
  42. Forensic_Report.html generated (standalone, base64 embedded, NIST SP 800-86).
  43. Examiner reviews results in PyQt6 workstation.
  44. Examiner closes PeakLedger window.

AUTO-COMMIT (CyberChain):
  45. peakledger_monitor_timer detects process exit (poll() returns non-None).
  46. Timer stops. auto_commit_session() executes.
  47. Exit time recorded (UTC ISO 8601).
  48. tamper_audit_report.json read from peakledger/evidence/.
  49. Verdict extracted: AUTHENTIC or TAMPERED with packet count.
  50. Merkle root extracted (first 16 chars logged).
  51. If tampered: divergence interval count logged.
  52. Forensic_Report.html existence checked -> courtroom admissibility change logged.
  53. Final change: "Session lifecycle concluded... Auto-committed on-chain."
  54. SessionAuditLedger.sol deployed to Anvil via Web3.py.
  55. recordSessionLogout() called with:
      - userId (usr_{username} or UUID)
      - username
      - sessionId (sess_{hex[:8]})
      - entryTime (UNIX seconds)
      - exitTime (UNIX seconds)
      - sqlModificationsCount (len of changes list)
      - sqlModificationsHash (0x + SHA-256 hex of JSON)
      - detailsJson (full JSON array, indent=2)
  56. Transaction receipt captured: contract_address, tx_hash, block_number, gas_used.
  57. On-chain verification: getSession(sessionId) called to confirm.
  58. database.record_smart_contract_session() called with all 16 fields.
  59. Anvil node stopped (terminate + wait + kill).
  60. Confirmation dialog displayed with full details.
  61. Application exits (QApplication.quit()).

POST-SESSION (Admin Console):
  62. Admin runs admin_app.py.
  63. Enters admin Name, authenticates via passkey.
  64. Role verified twice (pre and post passkey).
  65. Admin interface loads with 3 tabs.
  66. Tab 1: Selects session record from table.
  67. Full changes JSON displayed.
  68. SHA-256 hash recomputed from changes_json.
  69. Compared against stored changes_hash.
  70. Green badge: "✓ FORENSIC HASH VERIFIED" or Red: "⚠ HASH MISMATCH".
  71. Tab 2: Reviews all enrolled users and their passkey counts.
  72. Tab 3: Inspects SessionAuditLedger.sol source code.

                    PART G — SECURITY ARCHITECTURE

################################################################################
################################################################################

AUTHENTICATION LAYER:
  - Zero passwords. Zero emails. Zero shared secrets.
  - FIDO2/WebAuthn public-key cryptography only.
  - ES256 (ECDSA P-256) and RS256 (RSA PKCS#1 v1.5) supported.
  - Cross-device Bluetooth QR (hints: ["hybrid"]) for phone authentication.
  - Platform-local (Windows Hello / Touch ID) as fallback.
  - userVerification: "required" forces biometric (fingerprint/face).
  - Credential validation: empty/null/whitespace credential_id categorically rejected.
  - Cancellation (NotAllowedError) never triggers false verification.

ACCESS CONTROL:
  - Two roles only: 'user' (Forensic Examiner) and 'admin' (Administrator).
  - Role normalization: any input != "admin" (case-insensitive) defaults to "user".
  - Admin console: dual-gate verification (pre-passkey + post-passkey role check).
  - PeakLedger accessible to all authenticated users.
  - Admin console restricted to admin role only.

SESSION INTEGRITY:
  - Every session generates a unique session_id (sess_{uuid4.hex[:8]}).
  - Entry time and exit time recorded as UTC ISO 8601 timestamps.
  - All session modifications tracked in ordered list with index, timestamp, description.
  - SHA-256 hash computed over serialized JSON of all changes.
  - Hash stored on-chain (sqlModificationsHash) and off-chain (changes_hash).
  - Admin console performs live SHA-256 recomputation for integrity verification.

BLOCKCHAIN ANCHORING:
  - Anvil EVM node lifecycle bound to user session (starts on login, stops on logout).
  - SessionAuditLedger.sol deployed per-session (fresh contract each time).
  - recordSessionLogout() permanently records session data on-chain.
  - Duplicate session prevention: require(sessions[sessionId].entryTime == 0).
  - On-chain verification: getSession() called after recording to confirm persistence.
  - Block timestamp provides independent temporal anchoring.

CRYPTOGRAPHIC INTEGRITY:
  - PeakLedger Layer 1: SHA-256 Merkle Tree over ALL compressed video packets.
  - 100% cross-GPU/cross-CPU determinism (pure-integer arithmetic, no floating-point).
  - CyberChain: SHA-256 hash of session modifications for dual-persistence verification.
  - Combined: video integrity (Merkle root) + session integrity (changes hash).

FORENSIC STANDARDS COMPLIANCE:
  - Bharatiya Sakshya Adhiniyam (BSA) 2023, Section 63: electronic record admissibility.
  - NIST Special Publication 800-86: forensic evidence collection and reporting.
  - US Federal Rules of Evidence 902(13) & 902(14): self-authenticating digital records.
  - All reports standalone HTML with zero external dependencies.
